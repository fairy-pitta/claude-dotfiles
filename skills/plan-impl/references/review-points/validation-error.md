# 設計観点: バリデーション・エラーハンドリング

| 観点 | 設計段階での確認方法 |
|------|-------------------|
| **バリデーション実行順序** | 副作用（DB書き込み、外部API呼び出し等）の前にバリデーションが実行される設計か |
| **エンティティの不変条件** | ドメインエンティティが不正な状態で生成されないようバリデーションが計画されているか |
| **引数の整合性ガード** | 引数間に依存関係がある場合、呼び出し先でも防御的に検証する設計か |
| **エッジケースの考慮** | 境界値・ゼロ・空・null等のエッジケースが設計段階で考慮されているか |
| **エラーメッセージの定数化** | エラーメッセージが文字列リテラル直書きではなく、定数として管理される設計か |
| **ユーザー向け/内部向けの分離** | ユーザーに見せるメッセージと内部ログ用メッセージが分離されているか |
| **エラー時のロールバック** | トランザクション内で複数の書き込み操作がある場合、途中失敗時のロールバックが考慮されているか |
