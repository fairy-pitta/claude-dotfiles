# 設計観点: データベース・パフォーマンス

| 観点 | 設計段階での確認方法 |
|------|-------------------|
| **N+1クエリの回避** | リスト取得で関連テーブルを参照する場合、JOIN / eager loading の使用が計画されているか |
| **必要カラムの限定** | 全カラム取得ではなく、必要なカラムのみ取得する設計か |
| **インデックス設計** | フィルタ条件を変更・追加する場合、対象テーブルのインデックスが新しいクエリをカバーするか |
| **Bulk操作の検討** | 複数レコードの作成・更新でバッチ処理を使用する設計か |
| **ページネーションの安定ソート** | ソート順が明示され、同値タイブレーカー（PKなど）が含まれているか |
| **マイグレーションのロールバック** | データ破壊的なマイグレーション（カラム削除、型変更等）にロールバック策があるか |
