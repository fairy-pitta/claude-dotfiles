# 設計観点: DRY・コード組織

| 観点 | 設計段階での確認方法 |
|------|-------------------|
| **3箇所以上の重複防止** | 設計段階で同じパターンが3箇所以上に現れそうなら、共通化を計画しているか |
| **不要な中間層の排除** | 薄いラッパーやパススルーだけの中間ファイルを作っていないか |
| **単一責務** | 各関数・クラス・コンポーネントが1つの責務のみ担う設計か |
| **命名の明確性** | 関数名・変数名だけで中身が推測できるか |
| **依存追加の正当性** | 新規依存追加がある場合、標準ライブラリや既存の依存で代替できない理由が説明されているか |
