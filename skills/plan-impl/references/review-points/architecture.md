# 設計観点: アーキテクチャ

| 観点 | 設計段階での確認方法 |
|------|-------------------|
| **依存方向の一貫性** | 上位層→下位層の一方向のみか。逆方向の依存が設計に紛れ込んでいないか |
| **レイヤー間の責務境界** | 各レイヤー（Presentation / Application / Domain / Infrastructure）の責務が明確に分離されているか |
| **Domain層の純粋性** | Domain層がフレームワーク・ORM・インフラライブラリに依存しない設計か |
| **既存パターンとの整合** | 既存のエラーハンドリング、命名規約、ディレクトリ構成に従う設計か。独自パターンを不必要に導入していないか |
| **既存の定数・型の再利用** | 既存の定数・型定義・Enumがあるのに、同等の値を再定義する設計になっていないか |
| **モジュール間の結合度** | 変更が波及する範囲が限定されているか。密結合な箇所を新たに作っていないか |
| **公開APIの最小化** | 内部実装を不必要に外部に公開する設計になっていないか |
